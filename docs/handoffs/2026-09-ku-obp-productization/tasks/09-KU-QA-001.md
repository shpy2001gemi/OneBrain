# KU-QA-001 — Cross-surface local KU acceptance

> State: Planned
> Branch: `codex/ku-qa-001-cross-surface`
> Depends on: `KU-CLI-001`, `KU-DESK-001` and `KU-ENC-003` merged

## Objective

Prove that node service, REST/WS, CLI, local Web and Desktop produce the same KU
identity, lifecycle and error semantics across restart.

## Required read set

- package README/decisions/progress
- KU contract and all completed KU task evidence
- only source/tests needed to construct the acceptance harness

## Acceptance scenarios

- local create → preview/validate → save → retrieve/search;
- duplicate/idempotent retry and explicit conflict;
- immutable revision/supersession;
- process restart and durable parity;
- AI unavailable with allowed local operations retained;
- network unavailable with KU workflow retained;
- private-source/log/WebSocket leakage scan;
- CLI/API/Web/Desktop receipt and state equivalence.
- Same approved resolved SEM/profile compiles to exact bytes and identities
  across consumers; raw-text/model convergence uses KU-ENC-003 metrics and
  preserves legitimate alternatives instead of asserting universal equality.
- Same source/context/Registry/policy bindings and bounded extraction workflow
  on all surfaces, with partial coverage, unresolved, repair/cancel and privacy
  behavior projected consistently; no consumer-specific semantic defaults.

All assertions must be machine-readable and linked from the KU product profile.
No scenario may infer publication, Use, truth, Benefit or reward from viewing or saving.

## Excluded

Peer transfer, relay/NAT qualification and default rollout.
