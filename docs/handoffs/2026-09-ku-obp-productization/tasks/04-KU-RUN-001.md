## Objective

Implement the frozen KU product workflow once in a node-owned typed service so
CLI, API, Web and Desktop cannot diverge semantically.

## Required read set

- package README/decisions/progress
- KU authority audit, runtime gap map and merged KU product profile
- runtime ownership, lifecycle, concurrency and storage profiles implicated by
  the selected operations
- directly affected source modules and tests

## Scope

Implement service handles, durable owners, validation, idempotency, pagination,
restart recovery and typed status/errors required by the contract. Preserve
legacy reads/migration rules without granting legacy write authority.

Owner-approved scope extension (2026-09-05, D-016): perform the prerequisite
`semantic-content/1` registration and golden vectors, Base KU payload/DTO
registration, append-only history/compatibility revision and generated
projections before runtime dispatch. Update the corresponding contract gates
to require the actual registrations. Then complete the original service scope
and acceptance on this branch. The exclusions below continue to apply.

## Acceptance

- Service is the sole new mutation owner for contracted KU product operations.
- Canonical identity and validated storage survive restart.
- Duplicate requests are idempotent or return the exact contract conflict.
- Local functionality works with network and AI unavailable where the contract allows.
- No UI or transport layer reimplements KU semantics.
- Focused unit/integration tests, workspace check, format and contract validator pass.

## Excluded

REST handlers, CLI commands, Web/Desktop components and OBP orchestration.
