## Objective

Define one versioned framework in which local/personal AI proposes grounded
semantic candidates and deterministic host workflow controls resolution,
validation, compilation and KU service calls across platforms and models.

## Required read set

- package README, decisions, progress and master plan;
- [encoder research and overlap map](../outputs/KU_ENCODER_FRAMEWORK_RESEARCH.md);
- KU product, SEM, local Receptor encoder, observation intake, Registry and
  fidelity profiles; affected Base payload/resource rules;
- legacy encoder/extractor/analyzer/resolver/builder and structured provider
  interfaces; KU-RUN-001 input port and tests;
- existing MOB-06/architecture boundaries for interface compatibility only.

## Deliverables

- A shared framework specification under `docs/specs/vnext`, machine-readable
  context/candidate schema and schema-derived examples, prompt templates,
  feature/unsupported matrix, compile rules and private attempt evidence.
- Explicit source span convention, qualifier/scope/order representation,
  exact number/unit handling, chunk/context policy, Registry candidate binding,
  incomplete/partial coverage and repair/abstention semantics.
- Provider/resource contracts with aggregate budgets, cancellation, durable
  phase mapping to existing Base states and immutable resume/replay behavior.
- Reusable vi/en positive, negative, ambiguous and multi-chunk corpus;
  predeclared evaluation metrics and qualification gates for KU-ENC-003.
- Update existing authority/IDL registrations through their normal process
  only if necessary. Candidate DTOs are not canonical KnowledgeObjects.

## Acceptance

- No model-selected tools, fabricated CCIDs, first-candidate fallback, inferred
  certainty, hidden source correction or implicit publication/save.
- Same validated SEM/profile has exact identity; raw-text convergence is a
  measured quality property, not a deterministic guarantee.
- Every supported candidate construct maps to existing approved SEM. Missing
  coverage remains explicit; structural grounding is not a truth/fidelity proof.
- Prompt/schema/grammar versions cannot silently diverge; grammar support
  limitations are checked independently of semantic validation.
- No-LLM and resource-limited profiles retain the same semantic/authority
  rules. Model/runtime-specific prompt syntax stays inside adapters.
- New schema/corpus and contract validators pass; unresolved canonical
  conflicts are recorded instead of being implemented by inference.

## Excluded

Production inference/runtime changes, model qualification claims, new UI/API,
mobile implementation/evidence and changes to accepted object bytes.

Mobile consumption belongs to existing MOB-06 and KU encode gates; this task
does not reopen AI-001/AI-003/FID tasks or create a second mobile orchestrator.
