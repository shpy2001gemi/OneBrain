# KU-CON-001 — Shared KU product workflow contract

> State: Planned
> Branch: `codex/ku-con-001-product-contract`
> Depends on: `KU-REV-002` merged

## Objective

Freeze one additive, local-first KU product contract shared by node, REST/WS,
CLI, Web and Desktop before implementation changes.

## Required read set

- package README/decisions/progress
- `../outputs/KU_AUTHORITY_AUDIT.md`
- `../outputs/KU_RUNTIME_GAP_MAP.md`
- `../../../specs/vnext/ADDITIVE_KU_WORKFLOW_SURFACE_V1.md`
- existing vNext product/REST/WS/CLI/Desktop-Web profiles
- exact canonical KU/object/storage contracts named by the audit

## Scope

Specify create/prepare, validate/preview, save, retrieve, list/page, search,
revise/supersede, export and local status. Define typed identifiers, lifecycle,
coverage, errors, idempotency, restart behavior, privacy and publication
separation. Reuse existing fields/IDs where possible.

## Deliverables

- an additive owner-reviewable vNext KU product profile;
- machine-readable DTO/operation inventory where appropriate;
- validator and mutation tests;
- traceability back to audit decisions and existing canonical contracts.

## Acceptance

- No create/save/display action implies publication, Use, truth or reward.
- Immutable identities are never edited in place; revision/supersession is explicit.
- Raw/private source material stays within its declared storage/disclosure class.
- Every product surface can project the same state and error semantics.
- Any required new public wire ID or incompatible behavior is presented for
  owner approval rather than silently frozen.
- Contract/mutation validators and `git diff --check` pass.

## Excluded

Runtime implementation, screen styling, networking and default rollout.
