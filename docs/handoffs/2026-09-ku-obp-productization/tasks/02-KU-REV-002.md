# KU-REV-002 — KU runtime and product gap map

> State: Planned
> Branch: `codex/ku-rev-002-runtime-map`
> Depends on: `KU-REV-001` merged

## Objective

Map the authoritative KU workflow to current Rust storage/runtime, API, CLI,
Web and Desktop behavior and produce an evidence-backed implementation gap map.

## Required read set

- `../README.md`, `../DECISIONS.md`, `../PROGRESS.md`
- `../outputs/KU_AUTHORITY_AUDIT.md`
- this task's source modules and their directly associated tests/spec links

Start from `rg` references in `ku-core`, `onebrain-node`, `onebrain-api`,
`onebrain-cli`, `onebrain-web` and `onebrain-desktop`; do not read entire crates
when a narrower module owns the behavior.

## Deliverable

Create `../outputs/KU_RUNTIME_GAP_MAP.md` with:

- canonical operation → current owner/module/store/test/surface mapping;
- duplicate or divergent semantic implementations;
- stub/demo/in-memory-only behavior;
- restart, idempotency and migration evidence;
- missing shared-service/API work ordered by dependency and risk;
- proposed focused test commands for later tasks.

## Acceptance

- Separate implemented, partially wired, legacy and absent behavior.
- Do not infer completion from types or documentation alone.
- Record current focused test results without fixing failures.
- No application/source changes.
- Contract validator and `git diff --check` pass.
- Update progress and handoff evidence.

## Excluded

New public contracts, refactors, fixes and UI implementation.
