# KU-ENC-002 — Shared workflow-controlled local encoder

> State: Planned
> Branch: `codex/ku-enc-002-shared-encoder`
> Depends on: `KU-ENC-001` and `KU-RUN-001` merged

## Objective

Implement the frozen framework once behind the existing KU input provider and
node-owned service, with no separate semantic implementation in consumers.

## Required read set

Contract entry: [shared extraction framework](../../../specs/vnext/KU_EXTRACTION_FRAMEWORK_PROFILE_V1.md)
and [KU-ENC-001 evidence/limits](../outputs/KU_ENC_001_CONTRACT.md). The Python
oracle is specification tooling; implement the documented custody, Registry,
review authority and durable lifecycle preconditions in the native host.

- package README/decisions/progress and KU-ENC-001 deliverables;
- KU product/Base lifecycle/storage/Registry/SEM contracts;
- affected `ku-encoder`, `ku-ai` structured backend and node KU modules/tests;
- existing provider and custody ports, legacy read/migration boundaries.

## Scope

Bounded source/context preparation, rule and structured model extraction,
grounding and candidate validation, pinned Registry resolution, deterministic
SEM compilation, private attempt checkpoints, cancellation and one aggregate
repair/resource budget. Integrate through `KuInputProvider`; accepted writes
remain exclusively in KU-RUN-001. Reuse Ollama structured output support via a
provider-neutral interface; isolate backend-specific templates and options.

## Acceptance

- Corpus tests cover qualifiers, exact numbers/units, ambiguity, prompt
  injection, malformed/truncated output and missing cross-chunk context.
- Model-selected tool execution, direct storage, forged CCIDs and silent
  fallback into legacy CoreDna writes are impossible on the new route.
- No-LLM supported drafts/rules work offline; unsupported arbitrary text
  returns an explicit draft/dependency/coverage result.
- Same validated input compiles identically across qualified host fixtures;
  partial extraction cannot appear as full coverage or automatic ready/save.
- Current custody is checked before source use and writes; private prompts,
  outputs, context, identifiers and errors do not leak into logs/telemetry.
- Deadlines, cancellation, memory bounds, exhausted repair budget and process
  interruption have tested finite outcomes. Resume uses durable exact evidence
  and never replays a completed model attempt or confirmed save blindly.
- Shared workflow tests, node integration, contract validators, workspace
  check and format pass. Mock tests are labeled as such.

## Excluded

Default model selection/quality claims (KU-ENC-003), new REST/UI, remote work,
mobile native/provider integration, mobile evidence and unrelated legacy fixes.
